# 01 · 需求澄清与 PRD 摘要

## 一、需求澄清问题（5 个，不回答按默认值继续）

### Q1 学期规模与周次规则
- 问题：单学期总周数最大是多少？除「单/双周」外，是否还需要「每周 N 次不同节次」「调课周」等复杂规则？
- 默认：总周数默认 20、上限 60（受 `Long` 位图上限约束）；规则只做 4 种：`全部周 / 单周 / 双周 / 指定周次集合`。调课通过「指定周次 + 覆盖地点/备注」近似表达，不做独立的调课表实体。
- 影响面：`WeekMask` 位宽、周次选择器 UI、导入解析逻辑。

### Q2 节次规模与上课日范围
- 问题：一天最多多少节？是否包含周末、晚自习？节次时间是否所有学期一致？
- 默认：12 节/天，分上午(1-4)、下午(5-8)、晚上(9-12)；周一至周日全部可用；节次时间表**全局共享一份**（多学期复用），后续如需按学期差异化再加 `semesterId` 外键。
- 影响面：周课表行数、滚动性能、`TimeSlot` 表设计。

### Q3 导入素材格式
- 问题：你手上的 ICS 是标准导出（含 `RRULE`）还是只有单次事件？CSV 的列名是什么？
- 默认：ICS 按 RFC5545 子集实现（`VEVENT` + `DTSTART/DTEND/LOCATION/SUMMARY/RRULE`，`RRULE` 支持 `FREQ=WEEKLY` 配 `INTERVAL=1|2`、`UNTIL`、`COUNT`、`BYDAY`）；CSV 使用本项目提供的模板列名。不认识的属性**忽略并在预览页列出告警**，不静默丢弃。
- 影响面：解析器实现范围、预览页告警区。

### Q4 课前提醒的实现方式（**需要你决策**）
- 问题：Android 12+ 精确闹钟需要用户手动授予「闹钟和提醒」权限。是否接受为了准时提醒而申请该权限？
- 默认：接受。用 `AlarmManager.setExactAndAllowWhileIdle()`；若用户拒绝，自动降级为 `setWindow()`（±10 分钟），并在设置页显示「提醒可能延迟」提示。
- 说明：`WorkManager` 的周期任务最小间隔 15 分钟且有 Doze 延迟，**不适合做分钟级课前提醒**，只能用于小组件每日刷新。这不算更改技术栈，而是按需求「课前提醒，可配置提前分钟数」增加一个必要组件，特此显式说明。
- 影响面：权限清单、设置页、`ReminderScheduler`。

### Q5 多学期策略
- 问题：是否需要保存历史学期并来回切换？
- 默认：支持多学期并存，同一时刻只有 1 个 `isActive = 1`；切换学期会联动刷新周课表、今日页、小组件。
- 影响面：`course. semester_id`、学期切换 UI。

## 二、PRD 摘要

### 2.1 一句话定位
一个**纯本地、离线优先**的 Android 课表工具：手动录入或导入 ICS/CSV 后，用周课表、日课表和桌面小组件把「今天上什么课、在哪、第几节」在 3 秒内说清楚。

### 2.2 目标用户与场景
| 用户 | 场景 | 关键诉求 |
|------|------|----------|
| 大学生 | 早上出门前看一眼桌面小组件 | 不打开 App 就知道今天几节课、在哪 |
| 大学生 | 课间找下一节课教室 | 日课表 + 地点一眼可见 |
| 班委/学委 | 学期初把教务系统导出的一次性录完 | ICS/CSV 批量导入 + 冲突提示 |
| 转专业/重修 | 单双周、指定周次混杂 | 周次过滤必须准确 |

### 2.3 功能范围（In Scope）
1. **今日页**：日期横滑、当前周次、按时间排序的课程卡（课程名/节次区间/起止时间/地点/教师/颜色条）、空状态、点击进详情。
2. **周课表**：7 列 × N 节网格，左侧节次栏固定，课程块跨节合并显示，当前周高亮 + 当前时间线，可横纵滚动。
3. **课程管理**：课程 CRUD；一门课支持多个 `CourseSession`（多时段）；周次规则；冲突检测（同天同节 + 周次有交集）。
4. **学期与节次设置**：开学日期、总周数、当前周（自动推导/手动覆盖）、12 节时间可编辑。
5. **导入**：手动 / ICS / CSV（模板下载 + 预览 + 覆盖或合并 + 冲突提示）；`TimetableProvider` 接口 + `MockProvider`。
6. **桌面小组件**：Glance，今日课表，三档自适应尺寸，深色模式，条数上限 + 「还有 N 节」，点击进今日页，多触发源刷新。
7. **提醒与设置**：课前 N 分钟提醒、通知权限降级处理、主题/深色、JSON 备份恢复、隐私说明。

### 2.4 非目标（Out of Scope，明确不做）
- 社交、班级共享、云同步、付费墙
- 教务系统验证码识别/登录破解/抓包逆向
- 后台常驻保活、VoIP 级实时
- 多端同步、Web 端

### 2.5 合规红线（写进代码约束）
1. **不硬编码任何学校账号密码**；仓库中不得出现真实学号/密码字符串。
2. **不存明文密码**：未来真实教务适配器若需登录，凭据只能进 `EncryptedSharedPreferences`（AndroidX Security）或 Keystore，绝不入库、绝不写日志。
3. **不绕过验证码**：`TimetableProvider` 接口明确要求「官方 API / 导出文件 / 页面样本」三种合规路径之一；无样本则只能停留在 `MockProvider`。
4. **数据默认只存本地**：MVP 版本**不申请 `INTERNET` 权限**（无网络能力 = 无外泄路径），隐私说明里如实写。

### 2.6 成功指标（可自测，非商业指标）
| 指标 | 目标 |
|------|------|
| 冷启动到今日页首屏 | < 1.5s（中端机） |
| 周课表滚动 | 稳定 60fps，不丢帧 |
| 单次导入 200 条课程 | < 2s 完成解析与入库 |
| 小组件刷新延迟 | 数据变更后 < 1s |
| 单元测试覆盖核心逻辑 | 周次/冲突/解析 三类逻辑覆盖 ≥ 90% 分支 |
