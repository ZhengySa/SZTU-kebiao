# 14 · 成绩查询与流畅度优化

本轮两件事：**查成绩**（课程名 / 成绩 / 等级 / 绩点 + 总绩点 + 排名 + 学期切换）与
**把动画调顺**（原来液态背景每帧重绘，页面切换用的是框架默认的 700ms 转场）。

---

## 1. 成绩：真实页面长什么样

用真账号登录后把 `/jsxsd/kscj/cjcx_list` 抓下来核对过（夹具：`app/src/test/resources/fixtures/cjcx_list_all.html`）。

表头（16 列）：

```
序号 | 开课学期 | 课程编号 | 课程名称 | 成绩 | 总评成绩 | 成绩标识 |
学分 | 总学时 | 绩点 | 补重学期 | 考核方式 | 考试性质 | 课程属性 | 课程性质 | 通选课类别
```

### 三个坑

1. **等级列不叫「等级」，叫「总评成绩」。**
   `成绩` 是百分制分数（78），`总评成绩` 是等级（B），`绩点` 才是 3.0。
   一开始按「等级」找列，结果等级全是空的、绩点只能靠分数反推——数字看着对，来源是错的。

2. **「考试性质」也含「性质」二字。**
   认「课程性质」时如果不排掉它，`正常考试` 会被当成课程性质显示出来。

3. **这一版没有学期下拉框。**
   页面顶端只有一行「查询条件：开课时间【全部学期】」。所以"有哪些学期"只能从
   成绩行里归纳——只列出真正出过成绩的学期，反而更合用户预期。

### 请求方式

```
GET /jsxsd/kscj/cjcx_list                  → 全部学期（本校默认就是全部）
GET /jsxsd/kscj/cjcx_list?kksj=2025-2026-1 → 指定学期   （实测：当前学期"未查询到数据"）
```

GET 拿不到成绩表时再补一次 POST 表单（有的学校版本把查询绑在表单提交上）。

### 会话失效的判定

成绩页**不是** 302 到统一认证，而是直接返回教务系统自己的登录页（HTTP 200，
带 `LoginToXk` / `login.css`）。所以加了 `ZfGradeParser.isLoginPage()`，
命中就抛 `SessionExpiredException`，引导用户重新登录，
而不是显示"这学期还没出成绩"这种误导性文案。

## 2. 统计口径：和教务系统对得上

学校《学籍管理规定》第三十二条：

```
平均学分绩点 GPA = Σ(课程绩点 × 课程学分) / Σ 课程学分
```

页面顶部那一行本身就是官方统计：

```
所修门数:30  所修总学分:64.5  平均学分绩点:3.11  平均学分绩:79.09
已获得学分:64.5  专业绩点排名/专业总人数:95/157
```

本地按行重算的结果是 **3.1102**，四舍五入 3.11 —— 测试里直接把这个对齐关系钉住了。

几个细节：

- **分母只算有绩点的课**：1 学分的「通过」课（二级制）不进分母，
  所以参与绩点计算的学分是 63.5，而已获得学分是 64.5。
- **二级制课程**（通过/不通过）没有绩点，但合格了要算进"已获得学分"。
- **排名只认页面上的数字**：表格里没有名次，也不能自己算，所以
  `专业绩点排名/专业总人数:95/157` 是唯一来源；学校没给就显示"学校未提供"，不编造。
- 有附加题的课程总分能到 100 以上，这种情况无法从总分反推绩点，宁可空着也不猜。

## 3. 页面

入口：**设置 → 成绩 → 成绩与绩点**（底部栏已经 5 个 Tab，没再加）。

- 顶部统计卡：大号 GPA / 已获得学分 / 门数 / 排名胶囊
- 学期胶囊：`全部` + 各学期（横向滚动）。默认那一档一次就把所有学期拿回来了，
  本地按学期分桶，**点学期不联网**，直接出结果
- 课程行：课程名 + 学分/性质/考核方式 + 右侧成绩（百分制大号）+ 等级·绩点
- 颜色：≥90 蓝色、<60 红色、等级 F 红色
- 离线：上次成功的成绩写进 `grade_cache`（DataStore + JSON），
  会话过期时顶上一条红条写着"下面显示的是 X 月 X 日 X 时的缓存"，仍可查看

代码：

| 文件 | 作用 |
| --- | --- |
| `data/remote/sztu/ZfGradeParser.kt` | 表头驱动解析：成绩/等级/绩点/学分/学期/统计/排名 |
| `data/remote/sztu/SztuAuthClient.kt` | `fetchGradesHtml()`，含登录页判定与 POST 兜底 |
| `domain/usecase/SztuGradeUseCase.kt` | 每个学期一个独立 client（共享同一份 Cookie），可并发 |

## 4. 动画：把"每帧重画"改成"只挪图层"

### 4.1 液态背景（最大的一处）

老实现：

```kotlin
val drift1 by transition.animateFloat(...)   // 每帧变化
Canvas { drawBlob(center = f(drift1), ...) }  // 读它 → 每帧重画 5 个全屏径向渐变
```

`drawBlob` 是半径到屏幕 0.8 倍的径向渐变，一帧 5 个、60 帧/秒 = 每秒 300 次全屏渐变，
任何页面滚动都要跟它抢 GPU。

新实现：

```kotlin
Box(Modifier.fillMaxSize().drawWithCache { /* 画一次，缓存 draw 指令 */ })
    .graphicsLayer { translationX = driftX * 130f }   // 每帧只更新图层矩阵
```

- 光斑拆成两层（3 个 + 2 个），两层反向漂移，观感比原来更有"厚度"
- 图层放大 1.24~1.30 倍，位移时不会露边
- 漂移**故意跑在 ~12fps**（40 多秒一个来回，每帧位移不到 3px，60fps 纯属浪费），
  合成次数再降到 1/5
- 状态**只在 graphicsLayer 的 block 里被读**：Compose 只让图层失效，
  不重组、不重画 → 背景从"持续掉帧"变成"几乎零成本"

模拟器（swiftshader 软件渲染，比真机悲观得多）上量的静止画面开销：

| | 每 4 秒绘制帧数 | 单帧耗时中位数 |
|---|---|---|
| 改之前 | 158 | 48 ms |
| 改之后 | 43 | 20 ms |

### 4.2 页面转场

Compose Navigation 默认转场是 **700ms** 淡入淡出，按一下 Tab 要等半秒多才"到"。
现在是：

- 底部 Tab 之间：纯淡入淡出，170ms / 140ms（Tab 之间不需要方向感）
- 二三级页面（课程详情、成绩、设置项…）：横向位移 1/10 屏 + 淡入，280ms

### 4.3 底栏

选中态的图标颜色和缩放都走动画（`animateColorAsState` 200ms、`spring` 缩放 1.08），
不再是"啪"地跳变。

### 4.4 阴影

`GlassCard` 的阴影改成可传参（默认 12dp）；列表里的课程卡用 6dp。
每一层阴影都是一次离屏渲染，一屏七八张卡时它是滚动掉帧的主要来源。
