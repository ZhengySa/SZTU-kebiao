# 09 · 测试步骤与验收对照

> 本文分两部分：**怎么测**（命令与真机操作）和**逐条对照验收标准**。
> 凡是「需真机」的项，都是代码已完成但只能在手机上看到效果的部分（小组件、通知、闹钟）。

## 一、自动化测试

### 跑法

```bat
D:\xiangmu\build.bat :app:testDebugUnitTest
```

最近一次实际运行结果：

```
30 tests completed, 0 failed
BUILD SUCCESSFUL
```

报告位置：`app\build\reports\tests\testDebugUnitTest\index.html`
机器可读结果：`app\build\test-results\testDebugUnitTest\*.xml`

### 测试清单（30 个）

| 测试类 | 数量 | 覆盖什么 |
|--------|------|----------|
| `WeekMaskTest` | 7 | 位图构造、单周/双周/指定周、`contains`/`intersects`、`describe` 文案、60 周边界 |
| `WeekMathTest` | 8 | 开学日当周=第 1 周、开学前为负（`floorDiv` 而非 `%`）、跨年、`dateOf` 反算 |
| `ScheduleBuilderTest` | 4 | 按周过滤、按天分组、跨节课程起止时间、节次缺失时的兜底 |
| `ImportParsingTest` | 11 | ICS 周重复展开、`BYDAY` 多天拆分、单次事件落周、全天事件跳过、折行拼接；CSV 表头乱序/同名合并/双周/坏行容错/缺列拒绝；周次表达式各种写法 |

这几个类都是纯 JVM 测试（不启动 Android），跑一次约 0.2 秒，改逻辑后随手就能跑。

## 二、真机验收步骤（手把手）

前置：`adb install -r D:\xiangmu\app\build\outputs\apk\debug\app-debug.apk`

### 1. 手动建课并检查显示

1. 打开 App → 今日页右下角「+」
2. 课程名填「测试课」，地点「教三-201」，教师「张老师」，选个颜色
3. 时段：周一 / 第 1 到 2 节 / 每周
4. 保存 → 回周课表，看周一第 1-2 节是否是一整块、颜色是否正确
5. 回今日页，把日期滑到周一，看卡片是否显示：课程名 / 第 1-2 节 / 08:00-08:45（按你设的节次时间）/ 教三-201 / 张老师

### 2. 单双周与指定周次

1. 编辑「测试课」，把周次改成「单周」，保存
2. 周课表顶部把周次切到第 1 周（单周）→ 有课；切到第 2 周 → 没有
3. 改成「双周」再验证一次
4. 改成「指定周次」，只勾第 3、7 周 → 周课表只在第 3、7 周出现

### 3. ICS / CSV 导入

1. 准备一个 ICS（手机日历导出即可）或按模板写个 CSV
2. 设置 → 导入课表 → 选文件
3. 看预览：门数、时段数、「发现 N 处时间冲突」是否合理
4. 选「合并」→ 确认导入 → 周课表应能看到新课程
5. 再导入同一个文件一次 → 合并模式下同名课程会被跳过（不会变成两份）
6. 选「覆盖」再导入 → 之前手动建的课应被清空

### 4. 桌面小组件

1. 长按桌面 → 小部件 → 课表 → 拖「今日课表」到桌面
2. 有课时显示：课程名 / 第几节 / 起止时间 / 教室
3. 把今天所有课删掉 → 小组件显示「今日无课」
4. 点小组件任意位置 → 应打开 App 今日页
5. 把小组件拉成 4×4，条数应变多；拉成 4×2 时超出部分显示「还有 N 节」
6. 系统切深色模式 → 小组件背景与文字跟着变

### 5. 修改课程 / 切换周次后小组件刷新

1. 桌面上留着小组件
2. App 里改今天的课（改名或改地点）→ 回桌面看，应在 1 秒内更新
3. 设置 → 学期 → 手动把当前周改成下周 → 小组件内容应按新周次变化

### 6. 重启不丢数据

1. 完全杀掉 App（最近任务里划掉）→ 重新打开，数据还在
2. 手机重启 → 打开 App，数据还在；小组件也能正常显示（由开机广播恢复排程）

### 7. 深色模式

1. 设置 → 外观 → 深色：整个 App 变深色，文字可读
2. 切「跟随系统」，再把系统切深色 → App 跟着变

### 8. 课前提醒

1. 设置 → 课前提醒：打开，提前 10 分钟；若弹权限，允许通知
2. 建一门 10 分钟后开始的课（把节次时间临时改到对应时间）
3. 等到点，应收到通知「即将上课：课程名 · 08:00-08:45 · 教室」
4. 关掉开关 → 不应再收到

### 9. 备份与恢复

1. 设置 → 备份与恢复 → 导出备份文件，存到「下载」
2. 删掉几门课
3. 从备份恢复 → 被删的课应回来
4. 用文本编辑器打开 JSON，确认里面有学期、课程、时段，没有账号密码之类的东西

## 三、逐条对照验收标准

| # | 验收标准 | 状态 | 依据 / 怎么验 |
|---|----------|------|----------------|
| 1 | 手动创建课程并设置星期/节次/周次/地点后，周课表与今日页正确显示 | ✅ 代码完成，测试覆盖核心逻辑 | `ScheduleBuilderTest`（按周过滤、按天分组、跨节时间）；真机按上面第 1 步验 |
| 2 | 单双周、指定周次过滤正确 | ✅ | `WeekMaskTest` 7 个用例 + `ImportParsingTest` 周次表达式用例；真机第 2 步 |
| 3 | ICS/CSV 导入有预览、冲突提示，导入后完整显示 | ✅ | `ImportParsingTest` 11 个用例；预览/冲突/合并覆盖在 `ImportScreen` + `PrepareImportUseCase`；真机第 3 步 |
| 4 | 小组件显示今日课程（时间/节数/地点），无课显示空状态 | ✅ 代码完成，**需真机确认外观** | `TodayWidget` + `WidgetDataLoader`；真机第 4 步 |
| 5 | 修改课程或切换当前周后小组件能刷新 | ✅ 代码完成，**需真机确认时延** | `AppScheduleChangeNotifier`（300ms 去抖）+ 仓库层所有写操作都会通知；真机第 5 步 |
| 6 | 重启 App 数据不丢失 | ✅ | Room 落盘；真机第 6 步（含手机重启） |
| 7 | 深色模式正常 | ✅ 代码完成，**需真机确认对比度** | `ClassFlowTheme` + 小组件 `ColorProvider(day, night)`；真机第 7 步 |
| 8 | 关键逻辑有单元测试，项目可编译运行 | ✅ | 30 个单测全绿；`assembleDebug` 实际产出 `app-debug.apk`（22.4MB） |

## 四、还没做 / 已知限制（说清楚，不藏着）

| 项 | 现状 | 说明 |
|----|------|------|
| Compose UI Test（androidTest） | 未编写 | 需要真机/模拟器运行；核心逻辑已由 JVM 单测覆盖，UI 层建议在真机上按上面步骤回归 |
| 真实教务系统适配 | 只有接口 + Mock | 需要学校官方 API / 导出文件 / 页面样本，按需求约定不实现破解 |
| 小组件「每小时自动刷新」 | 无 | 只做每日 00:05 + 数据变更 + 系统事件三种触发；刻意不做高频轮询，省电 |
| 提醒的极端场景 | 部分厂商 ROM 可能杀闹钟 | 需要用户把 App 加入后台白名单，FAQ 里写了 |
| 周课表横向甩动的 1 帧抖动 | 可能存在 | 用的是「表头与内容共享 ScrollState」方案，兜底方案（自定义 Layout）写在 `docs/02-tech-design.md` |
